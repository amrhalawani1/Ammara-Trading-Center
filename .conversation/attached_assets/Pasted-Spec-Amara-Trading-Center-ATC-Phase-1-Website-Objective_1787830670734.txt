Spec: Amara Trading Center (ATC) — Phase 1 Website
Objective

Build the Phase 1 informative website for Amara Trading Center (ATC), a Jordan-based premium hardware and kitchen fittings distributor operating since 1977. This is NOT an e-commerce build — no cart, no checkout, no online purchasing. Phase 1's job is to translate ATC's in-person showroom credibility into a digital experience that converts visitors into either a trade inquiry (B2B: architects, fabricators, procurement) or a booked showroom visit (B2C: homeowners).

North star: every page should make a trade inquiry or a showroom visit feel like the obvious next step — without ever using loud, promotional, or urgency-based design or copy.

Success looks like: a site that reads as credible and restrained rather than salesy, that a workshop fabricator can get a fast answer from on his phone, and that a homeowner feels invited into rather than priced out of.

Brand & Design System — READ THIS BEFORE STYLING ANYTHING

ATC has two different brand documents in circulation. Use only the first one for this website. Do not blend them.

Use this (website system — locked):
Colors: Cream background (
#FAF5F5), ink/dark brown text (
#1A1212, 
#3D2828), red 
#C41A1A as accent only — never as a dominant fill, never for decoration, only for CTAs, links, and small emphasis marks.
Typography: Cormorant Garamond (serif) for all headlines and titles. DM Sans for all body copy and UI.
Tone — "Quiet authority": restrained, no banners, no discount language, no urgency ("limited time," "act now"), no stacked CTAs. One clear action per section, stated plainly.
Canvas: light/cream by default. Dark sections (e.g. a hero or quote break) are an intentional occasional contrast, not the default surface.
Do NOT use this (Instagram/social brand guidelines — different scope, different audience):
Red 
#7B1A1A, black 
#0A0A0A as default canvas, Montserrat typeface, and the "one CTA per Instagram post" caption formula. This system was written for @atc.jo social content, not confirmed for the website, and actively conflicts with the locked system above. If any reference material mentions this black/Montserrat/
#7B1A1A system, ignore it for this build.
Logo

Use ATC's official logo source files only (the /// stripes + grey "A" + red "MARA" wordmark). Never recolor, stretch, rotate, or redraw it. Minimum size 120px wide digital. Maintain clear space equal to the height of the /// stripes on all sides.

Tech Stack
Framework: Next.js (App Router)
CMS: Sanity — content model should map cleanly onto ATC's existing MySQL product database for a future Phase 2/3 migration; treat Sanity as the layer ATC's own team edits, not a one-time content dump
Styling: Tailwind CSS, configured with the design tokens above as custom theme values (don't hardcode hex values in components)
Hosting: Vercel
Not in scope for Phase 1: Medusa.js (reserved for Phase 3 e-commerce), any payment integration, any cart/checkout logic

Site Map & Content Requirements

Seven top-level pages, plus two reusable templates (Brand Page, Product Page). Full section-by-section content detail is in the project's Final IA & Content Requirements document — paste that file into docs/ia-content-requirements.md before starting. Summary:

Home — trust bar (heritage, brand count, showroom locations), dual-journey split (Trade vs. Retail), showroom teaser, footer
Brands & Products — All Brands directory, Brand Page template, Product Page template
Trade / B2B — RFQ form, "Why ATC" (single accountable portfolio pitch), Support & Training content
Showroom — locations (Al-Bayader, Al-Wehdat), philosophy, single "Book a Visit" CTA
Resources — brand guides, product care, spec tips
About Us — Our Story (Est. 1977), Vision/Mission, brand partnerships, Quiet Authority narrative
Contact Us — inquiry form, showroom addresses/phones, trade shortcut
Content status — build accordingly
Confirmed sections: build fully, write real copy from the source research
Candidate sections (Search & Filter, Shop by Solution, room configurator): build the UI shell and routing, but do not treat as committed scope — flag clearly in code comments as // CANDIDATE — pending scope confirmation
Open sections (Project References, WhatsApp as formal channel, curated-catalog selection criteria, Arabic/RTL): use clearly-marked placeholder content (e.g. a visible "Coming soon" state), never fabricated text, fake project names, or invented certifications
New sections surfaced late (ATC private-label brand, Training/Technical Support, Vision/Mission statements): include — these are sourced from ATC's official Company Profile
Personas Driving UX Decisions

Build with these five people in mind, not a generic "user":

Fadi (workshop fabricator, B2B) — mobile, on a job site, wants the fastest possible path from search to a confirmed part to a WhatsApp contact. Speed and clarity beat inspiration content on every page he touches.
Rana (design specifier, B2B) — desktop, needs showroom-quality photography and brand pedigree she can put in a client document without recreating it herself.
Yousef (institutional/hospitality procurement, B2B) — needs scale and accountability signals, not a product catalog. His flow currently breaks if Project References isn't live — build the section so it's ready to go live the moment clearance clears, rather than needing a rebuild.
Hala (homeowner, B2C) — mobile, price-anxious, needs craftsmanship/material storytelling to justify cost before she sees a number, and one low-pressure path to booking a showroom visit.
Zaid (internal showroom consultant) — not a public nav item, but a constraint: Brand and Product Pages need to hold up clearly on a showroom screen at a glance, mid-conversation with a customer.
Boundaries

Always do:

Use the website brand system (cream/
#C41A1A/Cormorant+DM Sans), never the Instagram system
Keep one clear CTA per section — no stacked or competing prompts
Mark Open/unconfirmed content visibly rather than filling gaps with invented copy
Structure Sanity schemas so Brand and Product content can later map onto the existing MySQL fields without a rebuild

Ask first:

Any change to the confirmed color palette, typography, or the "quiet authority" tone
Adding a feature not listed in the Site Map above (e.g. a cart, an account system, a chatbot)
Any RTL/Arabic implementation — scope is still unconfirmed

Never do:

Never build checkout, cart, or payment flows — explicitly out of scope for Phase 1
Never invent project references, client names, certifications, or founding-year facts not present in the source research
Never apply the Instagram Brand Guidelines' black-canvas/Montserrat/
#7B1A1A system anywhere on the website
Never treat Candidate features (configurator, Shop by Solution) as committed scope in the actual build — shell only
Success Criteria
All 7 pages and 2 templates render with real, sourced copy for every Confirmed section
Site is fully responsive, mobile-first (Fadi and Hala are both primarily mobile)
Trade inquiry CTA is reachable from every page in 1 click
Sanity schemas exist for Brand and Product content types, structured for future MySQL migration
No fabricated content anywhere — Open items show clearly-marked placeholders instead
Lighthouse performance score reflects fast load on standard mobile connections (this matters specifically for Fadi's on-the-job use case)
